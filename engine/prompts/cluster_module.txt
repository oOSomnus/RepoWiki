This is a recursive refinement pass for the existing module {module_name}.
Return child groups only: each group must be a coherent smaller module and the
union of the child component lists must cover the input component IDs exactly.
If the input is already small and cohesive, return one group only; otherwise
return at least two groups. The parent keeps its aggregate component list, so
do not remove IDs from the parent and do not invent IDs.

Do not stop at a directory-shaped grouping when the input is still large. The
host will invoke this same scope=module prompt again for every oversized child
until the configured depth/token limits are satisfied.

DO NOT include components that are not essential to the module.

Files marked `(artifact: <class>)` are build, CI, container, packaging, manifest, configuration, schema or script files. Their components describe how the system is built, packaged, shipped, configured and tested. They ARE essential: group them into a dedicated build/deployment/configuration module, or attach them to the module they configure. Never drop them.

Each component ID has the form `<file_path>::<name>`. Return the IDs EXACTLY as given — do NOT strip the `<file_path>::` prefix or shorten the ID to the bare name.
